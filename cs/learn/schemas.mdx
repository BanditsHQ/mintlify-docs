Schéma definuje sloupce, které Lasso extrahuje z vašich zdrojových dat. Představte si ho jako šablonu pro vaši tabulku.

## Definice sloupců

Každý sloupec má klíč, popisek a typ:

```json
{
  "key": "product_name",
  "label": "Product Name",
  "type": "text",
  "required": true
}
```

- **key** -- Strojově čitelný identifikátor (snake_case). Používá se pro přístup k datům v řádcích.
- **label** -- Lidsky čitelný název zobrazený v exportech a na dashboardu.
- **type** -- Datový typ, který má Lasso extrahovat. Viz níže.
- **required** -- Zda musí mít tento sloupec hodnotu v každém řádku.

## Sdílené atributy a pomocné sloupce

Čtení schématu a tabulky vrací pro každý sloupec `attribute_id` a `kind`:

- `kind: "attribute"` označuje kanonický sdílený atribut se stabilním UUID.
- `kind: "helper"` označuje pomocný sloupec lokální pro schéma nebo tabulku. Jeho `attribute_id` je `null`.

Katalog a trvalé nebo plánované synchronizační cíle přijímají pouze kanonické sloupce s `kind == "attribute"`.

Kvůli kompatibilitě lze při vytvoření nebo aktualizaci schématu obě pole identity vynechat. Server vytvoří nebo připojí sdílený atribut podle klíče. Pro lokální pomocný sloupec odešlete `kind: "helper"`. Při úplné aktualizaci schématu zachovejte serverem vydané `id` použití sloupce.

## Typy sloupců

| Typ | Popis | Příklad hodnoty |
|---|---|---|
| `text` | Prostý text | `"iPhone 15 Pro"` |
| `number` | Celé číslo nebo desetinné číslo | `999.99` |
| `url` | Platná URL adresa | `"https://example.com"` |
| `email` | E-mailová adresa | `"info@example.com"` |
| `date` | Datum nebo datum a čas | `"2025-03-10"` |
| `boolean` | Pravda nebo nepravda | `true` |
| `richtext` | HTML nebo markdown | `"<p>Description</p>"` |
| `format` | Výsledek formule s určeným `format_output_type` | `42` |
| `enum` | Jedna z předdefinovaných hodnot | `"electronics"` |
| `tags` | Pole řetězců | `["wireless", "bluetooth"]` |
| `image` | URL jednoho obrázku | `"https://cdn.example.com/img.jpg"` |
| `images` | Pole URL obrázků | `["https://...1.jpg", "https://...2.jpg"]` |
| `file` | Jeden soubor | `"https://.../manual.pdf"` |
| `files` | Více souborů | `["https://.../a.pdf", "https://.../b.pdf"]` |
| `json` | Libovolný JSON | `{"specs": {"weight": "187g"}}` |
| `relation` | Odkaz na jeden nebo více produktů Katalogu | UUID produktu nebo pole UUID |

## Automaticky generovaná schémata

Pokud si nejste jistí, jaké sloupce definovat, můžete nechat AI vygenerovat schéma ze vzorových dat:

<CodeGroup>
```typescript TypeScript
const schema = await client.schemas.generate({
  sample_data: "Product: iPhone 15 Pro, Price: $999, Color: Titanium",
  name: "Smartphones",
});

console.log(schema.columns);
```

```python Python
schema = client.schemas.generate(
    sample_data="Product: iPhone 15 Pro, Price: $999, Color: Titanium",
    name="Smartphones",
)

print(schema["columns"])
```
</CodeGroup>

AI analyzuje váš vzorek a odvodí vhodné klíče sloupců, popisky a typy.

## Opětovné použití schémat

Schémata lze opakovaně používat ve více tabulkách. Existující tabulky používají vlastní snapshot a po změně zdrojového schématu si zachovají původní definice sloupců.

Trvalé smazání uspěje jen tehdy, když schéma nemá extrakční tabulky, produkty Katalogu, mapování, pohledy, šablony, feedy, Shopify vazby ani odkazy z relačních atributů. Konflikt závislostí vrátí `409` a žádný zdroj nezmění.
