---
title: "Pagination"
description: "Use the page, cursor, or offset pagination model required by each Lasso endpoint."
---

Lasso uses three pagination models. Check the endpoint reference before iterating.

## Page-based pagination

Attributes, schemas, files, tables, rows, glossary terms, and credit usage accept `page` and `limit`. The shared defaults are `page=1` and `limit=25`; the maximum limit is `100`.

```json
{
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 25,
    "total": 143
  }
}
```

Increment `page` until `page * limit >= pagination.total`.

## Cursor-based pagination

Catalog lists return `next_cursor`. Catalog product listing uses `page_size` with a maximum of `200`. Catalog changes defaults to `page_size=100`. Product analytics activity uses `cursor` and `limit` with a default of `25` and maximum of `100`.

Pass `next_cursor` back unchanged. Treat cursors as opaque and do not construct or decode them.

```json
{
  "products": [],
  "next_cursor": null
}
```

For `/catalog/changes`, keep the `sync_timestamp` from the first page for the next synchronization cycle.

## Offset-based pagination

Webhook delivery history accepts `limit` and `offset`. Increase `offset` by the number of returned delivery records.
