Lasso uses a credit-based system for extraction and enhancement operations.

## What consumes credits

| Operation | Credit cost |
|---|---|
| **Table extraction** | Varies by file size and complexity |
| **Single cell enhancement** | ~2 credits per cell |
| **Bulk enhancement, regular column** | ~0.5 credits per column |
| **Bulk enhancement, Gallery Max image column** | 16 credits per column |

Enhancement responses include an estimate. For bulk requests, the current public handler estimates every column at 0.5 credits even when the table snapshot configures a Gallery Max image column. Use the Gallery Max rate above for that column.

## Checking your balance

<CodeGroup>
```typescript TypeScript
const balance = await client.credits.balance();
console.log(`${balance.balance} credits remaining`);
```

```python Python
balance = client.credits.balance()
print(f"{balance['balance']} credits remaining")
```
</CodeGroup>

## Tracking usage

View your credit transaction history with optional filters:

<CodeGroup>
```typescript TypeScript
const usage = await client.credits.usage({
  from: "2025-01-01T00:00:00Z",
  to: "2025-03-31T23:59:59Z",
  service: "ai_field",
});

console.log(`Total used: ${usage.total_used} credits`);
```

```python Python
usage = client.credits.usage(**{
    "from": "2025-01-01T00:00:00Z",
    "to": "2025-03-31T23:59:59Z",
    "service": "ai_field",
})

print(f"Total used: {usage['total_used']} credits")
```
</CodeGroup>

## Aggregated statistics

`GET /credits/stats` returns daily, module, service, user, and Lasso-table aggregates for an inclusive `YYYY-MM-DD` date range. It also returns the equally sized preceding period, monthly allocation, and configured cost-per-credit data. The maximum range is 1,830 days.

```bash
curl --request GET \
  --url "https://app.productlasso.com/api/v1/credits/stats?from=2026-08-01&to=2026-08-31" \
  --header "Authorization: Bearer $LASSO_API_KEY"
```

## Insufficient credits

The current public handlers do not consistently return `402` for insufficient credits:

- Synchronous Search and Enrich return HTTP `200` with an `error` field and no results.
- Enhancement returns `202` before the worker reserves credits. The affected enhancement cells later move to `error` status.

Check `GET /credits/balance` before starting a large operation and inspect the operation result or enhancement status instead of relying on HTTP `402`.
